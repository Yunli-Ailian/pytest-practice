## 三、文件之间的依赖关系

**一句话：上层只管要什么，下层只管怎么给。改一层，上面不用动。**

```
                    ┌─────────────────┐
                    │   pytest.ini    │  决定怎么跑（参数、marker）
                    └────────┬────────┘
                             ↓
                    ┌─────────────────┐
                    │   conftest.py   │  备料：base_url / session / account
                    └────────┬────────┘
                             ↓ 把 session、base_url 塞进测试函数
        ┌────────────────────┴────────────────────┐
        ↓                                         ↓
┌───────────────┐                        ┌─────────────────┐
│ tests/test_*.py│                        │  core/api.py    │
│  （用例层）    │─── TodoAPI(session, ──→│  接口封装层     │
│               │        base_url)       │                 │
└───────────────┘                        └────────┬────────┘
                                                  ↓ _request()
                                    ┌─────────────┴─────────────┐
                                    ↓                           ↓
                          ┌─────────────────┐         ┌─────────────────┐
                          │ core/context.py │         │ common/config.py│
                          │  全局 token     │         │  读 YAML 配置   │
                          └─────────────────┘         └────────┬────────┘
                                                               ↓
                                                        config.yaml
                                                  （地址、账号、超时）

                  所有请求最终打到 → mock_server/app.py
```

**逐条说明：**

| 谁 | 依赖谁 | 为什么 |
|---|---|---|
| `tests/*.py` | `conftest.py` 的 fixture | 不自己创建 session，声明就要 |
| `tests/*.py` | `core/api.py` 的 `TodoAPI` | 不拼 URL，只调方法 |
| `core/api.py` | `core/context.py` | 每次请求前看看有没有 token 要带上 |
| `core/api.py` | `common/config.py` | 读默认超时等配置 |
| `core/api.py` | `requests` | 真正发请求的库 |
| `conftest.py` | `common/config.py` | base_url、账号从配置读，不写死 |
| `common/config.py` | `config.yaml` | 读文件 |
| 全部 | `mock_server/app.py` | 请求的最终去处 |

**关键理解：** `tests/` 里**没有一条 URL 拼接、没有一个 header 拼接、没有一处密码**。它们全被压到下面几层了。这就是分层的目的——用例只管「我要验证什么」。

## 四、核心概念速查

### 4.1 pytest 是怎么认出测试的

| 类型 | 识别规则 | 例子 |
|---|---|---|
| 测试函数 | 文件名 `test_*.py`，函数名 `test_*` | `def test_login_success(...)` |
| fixture | 必须带 `@pytest.fixture` 装饰器 | `@pytest.fixture def session():` |

**两者是两套规则**，不通用。`fresh_todo` 当时报错就是因为它既不是 `test_` 开头、又没装饰器。

### 4.2 fixture 的 scope

| scope | 生命周期 | 典型用途 |
|---|---|---|
| `function`（默认） | 每个测试前后各一次 | 干净上下文、临时数据 |
| `session` | 整个测试会话一次 | 数据库连接、HTTP session、配置 |

### 4.3 `yield` vs `return`

```python
@pytest.fixture(scope="session")
def session():
    s = requests.Session()
    yield s          # 交出去，测试用
    s.close()        # 测试全跑完再回来执行这行
```

`return` 给完就结束；`yield` 给完还会回来做收尾。

### 4.4 `*args` / `**kwargs`

- **定义时**：收。`*args` 收位置参数成元组，`**kwargs` 收关键字参数成字典
- **调用时**：拆。`f(*args, **kwargs)` 把元组/字典摊开传进去

在本项目里的用处：`_request(method, path, **kwargs)` 把调用方传的 `json=`、`headers=` 原样转给 `session.request`。

### 4.5 类、`__init__`、`self`

```python
class TodoAPI:
    def __init__(self, session, base_url):   # 创建对象时自动跑
        self.session = session               # 存到对象身上
        self.base_url = base_url
```

- `__init__` = 入职填表，把参数记在自己名下
- `self` = 「我的」，`self.session` 读作「我的 session」
- Python 的 `self` 必须显式写，不像 Java 的 `this` 能省略

### 4.6 装饰器

```python
@log_time
def test_todo_crud(...): ...
```

本质是 `test_todo_crud = log_time(test_todo_crud)`，把函数包起来，**调用时机和方式归 wrapper 管**（能做重试、能记耗时、能改返回值）。

`@wraps(func)` 保的是**元信息**（`__name__`、`__doc__`、签名、`__dict__`），不是「收集资格」——装饰后模块属性名仍是 `test_xxx`，pytest 按**属性名**收集，照样能跑。

它真正兜底的是两件事：

- 调试和报告里看到的是原函数名，不是 `wrapper`
- mark 挂在**内层**时（`@log_time` 在外、`@pytest.mark.smoke` 在内），mark 落在原函数身上、wrapper 一点不带；`@wraps` 会把 `__dict__`（含 `pytestmark`）复制过来救回来

> 装饰器**从下往上**求值。mark 放最外层最安全——此时 mark 直接挂在最终暴露的对象上，有没有 `@wraps` 都不丢。
> （2026-11-01 实测：外层 mark + 无 wraps → 正常跑；顺序对调 → `-m smoke` 立刻 `1 deselected`。）

### 4.7 requests.Session

`requests.get()` 其实每次都临时开一个 Session、用完扔掉。手动 Session 的价值是**复用**：cookie、headers、连接池都留着。

### 4.8 token 自动注入

```python
token = context.get_token()
if token:
    headers = kwargs.pop("headers", {})
    headers["Authorization"] = f"Bearer {token}"
    kwargs["headers"] = headers
```

放在 `_request` 里，所以**用例永远不用手写 Authorization**。这是 AOP 思想：不改用例，在它周围织一层。

## 五、常见错误记录（错题本）

| # | 错误 | 现象 | 正确写法 |
|---|---|---|---|
| 1 | URL 没加引号 | `SyntaxError: invalid syntax` | 字符串必须加引号 `"http://..."` |
| 2 | f-string 漏 `f` | 打出来就是 `{base_url}` 字面量 | `f"{base_url}/todos"` |
| 3 | f-string 括号位置错 | `f"{base_url/me}"` 把字符串当除法 | `f"{base_url}/me"` |
| 4 | 变量名拼错 | `baswe_url` / `sefl` / `bae_url` | 改完扫一眼 IDE 的红线 |
| 5 | fixture 没写进参数 | `fixture 'xxx' not found` | 函数参数里点名 |
| 6 | fixture 没加装饰器 | 函数根本不执行 | `@pytest.fixture` |
| 7 | 类里的 logger 用裸名 | `NameError: name 'logger' is not defined` | 提到模块级，或用 `self.logger` |
| 8 | `self.x = self.x` | 属性还不存在就引用 | `self.x = x`（右边是参数） |
| 9 | `return` 写在 try 里 | 后面的日志永远跑不到 | 先赋值、记日志、最后 return |
| 10 | `timeout` 传两遍 | `got multiple values for keyword 'timeout'` | `_request` 管了，方法里就别再传 |
| 11 | `kwargs[headers]` | 字典当键，`unhashable` | `kwargs["headers"]` 键是字符串 |
| 12 | 元组当字典 | `TypeError: 'tuple' object does not support item assignment` | `{}` 不是 `()` |
| 13 | YAML 冒号少空格 | 整行被当成字符串，不报错 | `base_url: http://...` 冒号后必须空格 |
| 14 | `getenv` 少 `os.` | `NameError: getenv is not defined` | `os.getenv(...)` |
| 15 | 服务改了没重启 | 路由 404，代码明明是对的 | Flask 默认不热加载，改完必须重启 |
| 16 | 旧进程占着端口 | 起的"新"服务其实是老的 | `Get-NetTCPConnection -LocalPort 5000` 查 PID |
| 17 | 测试删了公用数据 | 单独跑能过、一起跑就挂 | 自己建自己删，用 `new_id` 不用 `1` |
| 18 | 文件没保存 | 报错说文件是空的 | 看一眼标签页有没有小圆点 |
| 19 | 改了环境变量没开新窗口 | `java` 还是找不到 | 关掉所有终端重开 |
| 20 | allure 双击 index.html | 404 | 用 `allure open` / `allure serve` |
| 21 | 把 `error` 当 `failed` 查 | 服务没起时报的是 error，不是 failed | error=fixture 阶段就炸=环境问题；failed=断言没过=用例问题。先看汇总行是哪个 |
| 22 | 分不清 Timeout 和 ConnectionError | 以为是同一类「连不上」 | Timeout=连上了但太慢（`Read timed out`）；ConnectionError=根本没连上（`WinError 10061`）。**跟 header/token 无关**，header 错只得到 401/403 |
| 23 | 以为不加 `@wraps` 用例会消失 | 实测照样 `1 passed` | 用例按属性名收集；丢的是 mark（挂内层时），只有 `-m` 过滤才变 deselected |

**归纳一下，反复出现的只有四类：**

1. **手不熟**（第 1、2、3、4 条）——只能靠敲，但可以靠「写完扫一眼」提前发现
2. **规则没记住**（第 5、6、7、10、11、12 条）——这些是概念，不是手感
3. **环境问题**（第 15、16、19 条）——改完必须重启/重开，这跟代码无关
4. **想当然**（第 21、22、23 条）——术语听过就当懂了，一动手实测就现原形。治法只有一个：**自己跑一遍**

## 六、调试方法

### 6.1 看报错

- **从下往上看**：最后一行是结论，上面是现场
- **报错位置 ≠ 出错位置**：断言失败在 `assert` 那行，但真正的坏点可能是上游给的返回值
- **`KeyError`**：字典没这个键，先看服务端到底返回了什么
- **`AttributeError: 'NoneType'`**：某个函数没 `return`，默认返回了 None

### 6.2 常用命令

| 场景 | 命令 |
|---|---|
| 只跑这一个用例 | `pytest tests/test_auth.py::test_login_success` |
| 按关键字筛 | `pytest -k crud` |
| 只跑上次失败的 | `pytest --lf` |
| 第一个失败就停 | `pytest -x` |
| 看 print 输出 | `pytest -s` |
| 按标记筛 | `pytest -m smoke` |

### 6.3 排查环境问题

```powershell
Get-NetTCPConnection -LocalPort 5000 -State Listen | Select-Object OwningProcess
Get-CimInstance Win32_Process -Filter "ProcessId=<PID>" | Select-Object CommandLine
Stop-Process -Id <PID> -Force
```

## 七、现在这套东西的价值（面试怎么讲）

**讲三段：**

1. **框架怎么分层**：用例只管业务断言，接口封装在 `core/api.py`，token 全局管理在 `context`，配置外置在 YAML。改环境只改配置，代码一个字不动。

2. **为什么要这么分**：一开始所有东西写在一个文件里，改一个地址要改十处；后来拆成四层，**每一层只干一件事**。这跟你没法学过的 SSM 是同一个思想——上层不知道下层怎么实现。

3. **踩过的坑**：测试依赖于公有数据 1 号，别人一删就全挂；改成自己建、自己删之后就独立了。这个叫测试隔离性。

**再补一句 AI 相关的：** 框架最初是 AI 辅助生成的，中间出错的部分是自己改的——比如 `timeout` 重复传、`return` 位置错、YAML 缩进。这说明有独立排查能力。
